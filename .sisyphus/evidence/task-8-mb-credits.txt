## Module API

### `fetchRecordingCredits(mbid: string): Promise<TrackCredit[]>`
Fetches artist-recording relationships for a single recording from MB API.
- Endpoint: GET /ws/2/recording/{mbid}?inc=artist-rels&fmt=json
- Rate limited to 1 req/sec
- Returns empty array for 404/400 responses
- Throws on other HTTP errors

### `fetchReleaseCredits(recordingMbids: string[]): Promise<Map<string, TrackCredit[]>>`
Fetches credits for all recordings in a release, respecting rate limits.
- Iterates sequentially with 1 req/sec rate limiting
- Returns Map from recording MBID to TrackCredit[]

### `normalizeRole(mbRelType: string): string`
Normalizes MB relationship type names to consistent role strings.
- Maps: producer→producer, engineer→engineer, mix→mixer, mixer→mixer, mastering→mastering, recording→recording, performer→performer, instruments→instruments, vocal→vocalist, vocals→vocalist, arranger→arranger, orchestrator→orchestrator, remixer→remixer, editor→editor, programmer→programmer, djmix→djmixer
- Unknown types preserved as-is for review

### `rateLimitedFetch(url: string): Promise<Response>`
Rate-limited fetch enforcing 1 req/sec to MusicBrainz API.
- Uses proper User-Agent header: mirmir/0.1
- Module-level rate limiter with resetRateLimiter() for testing

### `relationToTrackCredit(relation: MBArtistRelation): TrackCredit`
Converts a single MB artist relationship to TrackCredit.
- name = artist.name
- role = normalized from relation.type
- sources = ["MusicBrainz"]
- mbid = artist.id
- externalIds = [{ provider: 'musicbrainz', type: 'artist', id: artist.id }]

### `recordingResponseToCredits(response: MBRecordingResponse): TrackCredit[]`
Converts all relationships from an MB recording response to TrackCredit[].

## TrackCredit Fields

Each credit from MB has:
- `name`: Artist name from MB
- `role`: Normalized role string
- `sources`: ["MusicBrainz"]
- `mbid`: MB artist UUID
- `externalIds`: [{ provider: 'musicbrainz', type: 'artist', id: artist.id }]

## Design Decisions

1. Rate limiter uses module-level state (lastRequestTime) — simple, works for sequential access
2. MB API errors (400/404) return empty array instead of throwing — graceful degradation
3. Response body is cancelled on error paths to avoid Deno resource leak detection
4. Unknown MB relationship types preserved as-is (not flagged as "unknown") — allows forward compatibility
5. Module is UI-triggered, not automatic — respects rate limits and user intent
